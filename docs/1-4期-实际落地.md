## 一个贯穿四期的判断

清单把 20 多个机制按期排开，但其中相当一部分是**同一个问题的不同外壳**。
照单全做的结果是四五套 UI 干一件事，而这游戏跑在 iPhone 上，侧栏只有 64px、
状态框只有三槽。所以每一期都先做合并，再动手。合并的依据写在各条下面。

### 缓期（灰线债务条 + 产出路由）

原样做不成，两条都不成立：

- 「灰线排队、消行抵债」—— 灰线周期最快也有 7 秒，队列永远只有 0 或 1 行，
  债务是个空壳。
- 「消行抵债」等于把绝对压力钟拆掉。代码里写明灰线是全局唯一跟手速无关的
  压力源，拆了它整个难度曲线就没有底。

保留的是两者**各自真正的价值**：让压力可见（债务条）、把产出投给生存（产出路由）。
成品是：灰线还剩 8 秒时状态框给一个按钮，花热度把灰线钟往回推 9 秒，一行一次。

两个数值决定：

1. **推回固定秒数，不是周期比例。** 按比例推的话开局能推 21 秒、后期只能推 4 秒 ——
   正好跟需求反着来，你最需要喘气的是后期。
2. **价格是热度的固定比例（18%，下限 150），不是固定值。** 固定值在热度 5000 时
   等于白送、在热度 200 时又贵到没人用。按比例收则穷富一个价：倍率过拐点后是
   sqrt 压缩的，扣 18% 热度约掉 9% 倍率，与你有多少热度无关。

### ZONE

十秒内重力、灰线、事件三个钟全停；这期间消掉的行不消失，沉到底部变成死行，
地板一格一格往上涨；最多沉 12 行提前结算，结束时死行一次清空，按行数平方给奖金。

**为什么不是第四个「限时加倍窗口」**：FEVER ×4 二十秒、燃点 ×1.6 八秒、
梭哈按档结算 —— 已经有三个了，再加一个平倍率的等于什么都没加。
ZONE 的价值在形状不同：它是唯一一个拿盘面空间换分数的机制。

**刻意的简化**：ZONE 期间消行照常计分、照常推连击/B2B/梭哈行数，ZONE 只在
结束时额外给奖金。把得分推迟到结算听着更带感，但那会让「一次消除」变含糊，
betLines / combo / b2b / 彩虹行 / 压哨全要跟着改 —— 评审里点过这个坑。

## 第 2 期

清单六条（波次制 / 局内升级三选一 / 热度商店 / 开局三选一 / 血契 / 每局契约）
收成了**一套**：修行。

- 波次制 vs 局内升级三选一：评审标了「必须二选一」。这游戏是无尽刷分，
  波次制要重构整个对局结构，升级是加法 —— 选后者。
- 血契（有代价）和每局契约（有条件）本质上就是选项池里的两类卡。
- 热度商店和升级三选一是同一件事的两种付费方式。而热度已经有换牌 / 挪列 /
  缓期三个出口，再加第四个只会把每个都稀释掉。
- 分段结算：没找到它解决什么问题，没做。

**成品**：开局三选一 + 每 50 行再选一次，12 张卡（9 强化 + 3 血契），
同时最多挂两张血契，已选过的不再出现。

**实现上只有一个约定**：每张卡声明自己乘在哪个字段上，计算点统一读 `upMul()`。
加一张卡不用碰任何计算代码。测试里有一条就是遍历所有卡的字段逐个确认
真有计算点读它 —— 写的时候 `tau` 就是这么被抓到漏接的。

## 第 3、4 期

剩下的条目里挑了**成本最低、变化最大**的那一类：事件表和变异块表都是
数据驱动的，加内容不用碰逻辑。

- 新事件：顺风（热度翻倍，8 秒）/ 重影（没有落点虚影，7 秒，已进高危名单）/
  拾穗（队列前 3 块变成变异块，瞬发）。有利事件权重 38.5% → 48.6%。
- 新变异块：分流 1/140（格子各自落到底，治地形不平）/ 染色 1/150
  （把彩虹行标在自己指定的行）。

### 没做的，以及为什么

| 条目 | 不做的理由 |
|---|---|
| 蓄行 | 和 ZONE 是同一个东西 |
| 阶梯赌 | 梭哈已经是分档结算，加一层只是把同一条曲线拉长 |
| 死因礼包 / 段位认定局 | 刷分游戏里这类安慰奖只会摊薄每一局的分量 |
| 开局地形 | 只增加难度，和「两种对局都要能打出高分」的方向相反 |
| 锯齿死线 | 和现有危险区争同一个表达位 |
| 病毒格 | 第四种会扩散的负面状态，而负面已经够多了 |
| 成就系统 / 每日种子 / 倒计时局 | UI 面大，留到有真实分布之后再评估 |
| 单格块 / 五格块 | 会动 SRS 旋转和 wall kick，标准版共用这套代码，风险不对等 |

## 写的过程中抓到的真 bug

1. **`ZONE = 'Z'` 和 Z 型方块撞字母。** 后果不只在 ZONE 里 ——
   一整行 Z 块会被判成「死行」永远消不掉，因为那条扫描一直在跑。
   已改成 `'@'`，并给 `tools/audit.py` 加了格子标记撞车检查。
2. **炸弹 / 激光 / 重锤 / 地震都会改写死行。** 打穿之后那行不再是
   `every(c === ZONE)`，于是既不会被当满行消掉、也不会被 `zoneEnd` 清掉，
   永久卡在盘底。加 `zoneFloor()` 当地板，四个工具一律在它之上收手。
3. **彩虹行的行号迁移在 ZONE 下方向是反的** —— 地板在涨，消行之上的堆原地不动、
   之下的堆被抬高，和普通塌陷正好相反。
4. **`applyClear` 里直接调 `zoneEnd`** 会对着还没赋值的旧盘面动手。
5. **`--au-ring` 是 `syncEdge()` 内联写的，CSS 压不过。** 这个坑燃点栽过一次、
   代码里也写了注释，我还是又踩了一遍。
6. **缓期的 `popScore` 按 2 个参数调的，实际要 6 个。**

另外清掉了先前积压的六个缺陷（`'灰线挤死'` 不在 `DEATH_TEXT` 里、破纪录漏判、
暂停图标不复位、险中求生漏 `syncEdge`、燃点和热度衰减读两个不同的时钟）。

## ⚠️ 还欠一件事：梯子没重标

ZONE 约 +20%，修行四次选择估计再 +40~50%，合计可能到 **1.7 倍**。

这一轮**必须等真人打几局**。机器人不是有效数据源 —— 同种子跑出 56~175 行，
峰值热度和真人差 13 倍。它只能用来验结构（曲线连续性、单调性、同条件下的比值），
不能用来定阈值。
