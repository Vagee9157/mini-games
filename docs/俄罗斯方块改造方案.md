### A1. 计分与等级

### A2. 灰线

| 事实 | 依据 |

## B. 待决问题 —— B1~B3 已用 harness 实测（2026-09-24）

> 阶段 -1 已完成。下面是 harness 跑出来的真实答案，**它推翻了 v1~v3 的核心前提**。

### B1（已答）：留井打 TETRIS —— 优势只有 1.12×，而且更容易死

同样 60 行、等级进程完全相同、同种子对跑，各 24 局：

| | 贪心 bot | 专打 TETRIS bot | 倍率 |
|---|---|---|---|
| 有灰线 | 25,274（24/24 活满，四行占 0%）| 28,318（**22/24 活满**，四行占 10%）| **1.12×** |
| 无灰线 | 25,332（24/24 活满，四行占 0%）| 29,332（24/24 活满，四行占 14%）| **1.16×** |

**纸面推算的 2.82×（修正后 2.0×）是错的。** 错因：它假设玩家能把 60 行全打成 TETRIS，而**连专门为此写的 bot 也只有 10~14% 的行是四行消**，其余照样是单双行。风险调整之后基本打平。

**连带结论**：

1. **教学不能教"留井打 TETRIS"** —— 在我们这套机制里这条建议近乎无用，教了反而让人死得更快（活满率 22/24 vs 24/24）
2. **灰线 P0 问题是真的，但量级很小** —— 关掉灰线，四行占比 10%→14%、优势 1.12×→1.16×。确实在破坏井，但修好它只值这点
3. **真正决定分数的是活多久**，不是消得好（见 B3 的完整局数据）

### B2（已答）：combo 占总分 12.6%（贪心）/ 6.4%（TETRIS bot）

确实在偏袒"见行就消"，也确实过了"超过 10% 才值得动"的线 —— 但它不是主因，动它最多把 1.12× 推到 1.2× 上下。

### B3（已答）：死因分布 —— **灰线从来不直接杀人**

完整局各 20 局：

| | 锁在隐藏区 | 出生撞死 | 灰线顶出 | 灰线挤死 |
|---|---|---|---|---|
| 贪心 bot | 65% | 35% | **0%** | **0%** |
| TETRIS bot | 45% | 55% | **0%** | **0%** |

灰线只是把堆推高，真正的死亡永远发生在"新块出生时撞上"或"锁在隐藏区"。

> **这一条顺带废掉了一个旧基线**：v1~v3 表格里的"死于灰线 41% / 25% / 39%"来自那份 Python 平行实现，真实游戏里是 **0%**。v3 §D 的验收③（死因四桶各自相对基线偏移 ≤15 个百分点）必须按这组新基线重写。

## B'. B1 的结论对方案意味着什么

**方案原来的逻辑链断了。** v1~v3 的主线是「灰线机制阻碍 TETRIS 打法（P0）→ 修灰线 → 教玩家打 TETRIS → 分数翻三倍」。实测证明最后一环只值 1.12×，前两环的价值随之坍塌。

摆在面前的是两条路：

**路线甲：接受"打法不影响分数"，把力气放回原始诉求。**
用户最初问的是"怎么更爽"和"加随机奖励机制"，**"教 TETRIS"是我自己加的戏**。那就砍掉教学和灰线 P0，只做：反馈手感（§E2）、音乐音效（§E3）、疯狂版（§E4）。这条路风险最低，而且直接对着原始需求。

**路线乙：如果希望打法真的影响分数，要改的是计分本身。**
不是修灰线、不是加教学。可选的旋钮：
- TETRIS 基础分 800 → 1200（拉开与 4 次单行 400 的差距）
- B2B 从 ×1.5 提到 ×2
- combo 只在 hard clear（TETRIS / T-spin）上累计 —— 直接消掉 B2 那个反向激励

这条路要重新跑 B1 确认改完真的分离了，**而且会让所有老分数不可比**（又要清一次档）。

**我的建议是甲。** 理由：B1 说明打法差距在这个游戏里天然就小（四行消最多占 14%），硬把它撑大需要动计分核心，收益是"让一个人玩的小游戏更有策略深度"，代价是再来一轮完整的调参和验证。而原始诉求（更爽、有惊喜）走路线甲就能满足。

## C. 阶段 -1：建立可信的测量（唯一完全指定的阶段）

**这是当前唯一可以立刻动手、且不依赖任何待决问题的工作。**

### 要做什么

**1. 随机源分流（不是统一）**

```
rndGame()  ← 只管 7-bag(:370) 和灰线缺口(:656)，吃种子
rndFx()    ← 粒子(7处) 和噪声音效(2处)，保持 Math.random
```

v2 写"所有 `Math.random()` 收敛成一个 `rnd()`"是错的：粒子数量随局面变化、`sfx` 在静音时直接 return 根本不调噪声，共用一条流会让**同一个种子下"开音效"和"静音"洗出不同的袋**，A/B 对比直接失效。

**2. 把 `tick` 拆成 `step(dt)` + `tick(now)`**

现在 `tick(now)` 第一行就自己排 rAF、参数是绝对时间戳、`dt` 被 `Math.min(..., 100)` 锁死。直接导出没法用。拆成：

- `step(dt)` 只做逻辑，内部按 ≤100ms 切片循环 → harness 一次能喂 1000ms
- `tick(now)` 退化成"算 dt + 调 step + 排 rAF"

**3. harness 拆成两条，不要混**

| | 规则 harness | 真机回归 |
|---|---|---|
| 跑在 | Node + jsdom + canvas stub | headless Chrome |
| 验 | 规则、分数、难度曲线、bot 对比 | 布局、渲染、音频、iOS 挂起、五个压力场景 |
| 为什么分开 | `layout()` 在 jsdom 里 `clientWidth` 恒为 0 会直接早退（`:720`），CELL 永远是默认值 —— **渲染类的东西在 jsdom 里一条都跑不了** |

canvas stub 必须在脚本求值前装进 `HTMLCanvasElement.prototype` —— 模块级 `:694` 就 `getContext('2d')`，jsdom 返回 null 会让 `init()` 末尾的 `draw()` 当场 TypeError。

**4. 两只 bot 一起做（它们是 harness 的组成部分，不是阶段 0 的产出）**

- 贪心 bot（现有 El-Tetris）
- **TETRIS bot**：留井 + 只在四行满时下 I 块

v2 把 TETRIS bot 排在阶段 0，但阶段 -1 的验收要"跑出三档基线"——跑基线就得有 bot，循环依赖。

**5. 用 harness 产出 B1~B4 的答案**，写回本文档 §B。

### 验收

- 同种子两次跑出**完全相同**的结果，**且与音效/粒子开关无关**
- 规则 harness 跑出的三档基线与真机实测吻合
- 一轮扫参从 10 小时降到分钟级
- 产出：死因四桶基线分布、combo 占比、TETRIS bot vs 贪心 bot 的分数分布

## D. 阶段 0：机制修正（依赖 §B 的答案）

**前置**：B1~B4 必须有数。

### 拆成两个独立小步，不要一起改

v2 把 combo 和灰线缺口放在同一阶段，通过了也分不清是哪件事的功劳。

**0a. combo**（仅当 B2 显示占比 >10% 才做）
**0b. 灰线缺口**

### 0b 的改法

缺口列改成**分段共用**，但**不用概率**：

> v2 写"20~30% 概率换列"。问题是一局只有 4~16 行灰线，p=0.2~0.3 的几何分布在这个样本量下**方差压过信号**：普通档 7 行全落同一列的概率约 26%（白送一次 TETRIS），全换列则退化回现状。而验收正好要卡 p90 —— 拉宽分布的恰恰是这个改动本身。

改成**每段 3~5 行、段长均匀随机**（有下限，方差可控），换列时**不限制新旧列距离**（v2 写的"至少隔 2 列"恰好排除了玩家唯一能一次挖通两组灰线的情况，是加重不是减轻）。

**兜底要写对**：`clamp` 对 `undefined`/`NaN` 无效（A4），必须写成

```js
const gap = Number.isInteger(gapCol) ? clamp(gapCol, 0, COLS-1) : (rndGame()*COLS)|0;
```

并在 `riseGarbage` 补断言：新行必须恰好有一个 `null`。

### 存档 schema 一次定死

- 加 `v` 字段
- 策略是**"缺字段取默认值、不丢档"**，不是"版本不符直接丢" —— 后面阶段 1 要加复盘统计字段、阶段 3 要加 mod 字段，丢档策略会让每次加字段都清掉用户进度
- `gapCol` / `gapLeft` 进存档

### 清档

bump `WIPE_TOKEN`，旧值存成 legacy 并在结算页显示。**两个坑**：
- legacy key 要走 NS，不能写死 `tetris.` 前缀
- 写入要加条件 `if (had > 0 && had > readLegacy())`，否则第二次清档会把 legacy 覆盖成 0

### 验收（双边 + 相对基线）

| # | 指标 | 阈值 |
|---|---|---|
| ① | 熟练档时长 | **6~10 分钟** |
| ② | 普通档分数 | 中位 **20,000~40,539**（=25,337×1.6）且 **p90 ≤ 基线 p90 × 1.8** |
| ③ | 死因分布 | 四桶各自**相对 B3 基线偏移 ≤15 个百分点**（不用绝对阈值，因为 spawn 桶基线可能本来就 50~60%）|
| ④ | 无稳态平台 | 贪心 bot 在 level 20 前不出现 ≥3 分钟的消行速率平台 |
| ⑤ | **打法分离度** | **改后分离度 ≥ 改前（B1 基线）+ 明确增量**。不用绝对阈值 —— v2 的"TETRIS bot p25 > 贪心 p50"没有前置测量、不可证伪，而且 p25 对高方差策略有系统性偏见（留井本质上是拿死亡风险换高分）|
| ⑥ | 灰线改动本身不得拉宽分布 | p90/p50 比值相对基线扩大 ≤ X%（X 由 B4 定）|
| ⑦ | 回归 | 标准版功能回归全过 |

## E. 待办清单（阶段 1 以后 —— 有设计方向，但不假装是规格）

阶段 -1 和 0 没做完之前，下面这些的数值和优先级都不可信。这里只记**方向**和**已经知道会踩的坑**。

### E1. 教学（方向明确，性价比最高）

- **不能只做"首次达成"型** —— 打不出 TETRIS 的人永远触发不了"首次 TETRIS"提示，教学对最需要它的人不生效
- **但"连续 5 次单行"这个前置触发器有毒**：灰线每行一个独立缺口，玩家把缺口填上就是一次单行消除 —— **灰线机制天然量产连续单行**。那一刻弹"试试留空一列"，而玩家盘面底部已经有一列被灰线钉死，等于劝他同时维护两口井。触发条件必须排除"含 GARBAGE 的消除"
- **局末复盘是教学效率最高的一环**（唯一会让玩家停下来看的界面，纯 UI 零机制风险）：单/双/三/TETRIS 各几次、最长 B2B、最高 combo、一句针对性建议
- 必须提 **hold 和 next 队列** —— 留井打法离开 hold 根本执行不了
- 删掉"首次全消"那条：全消只在开局前 45 秒可能发生，那时 `levelMult`=1.0，奖励 800~2000 分（**是乘倍率的**，但 L1 倍率就是 1），连一次 L9 的 TETRIS（3,727）都不如
- 教学已读标记用**独立 key，不受 `WIPE_TOKEN` 影响**
- **复盘统计字段要进存档**，否则"接着玩"回来复盘是空的 —— 这意味着阶段 1 也要动存档 schema

### E2. 反馈与手感

已知约束（全部来自 §A）：

- **徽章绝对定位，不能进 `#boardWrap` 布局流** —— `ResizeObserver` 会因高度变化重算 `CELL`，徽章一亮一灭棋盘就跳尺寸 + 全盘重绘
- **震屏挂 `.board-box` 的内层新元素** —— 挂 `#board` 会和 `#board.flash-big` 抢 `animation` 属性（TETRIS 正好两个都要）；挂 `.board-box` 本身要处理它的居中 `transform`
- **塌落位移塞进现有 260ms**，而且那 260ms 是满帧的，性能预算按 60fps 算
- **危险提示不能用边框** —— 等级边框已经走到品红 + 满级常亮脉动，熟练档后半段本来就是红的
- **落地 squash 要么补约束（squash 期间延后 `stampToStatic`），要么砍掉** —— 它是收益最低、耦合最深的一条
- **破纪录提示、分数滚动只能放 DOM** —— 结算页和暂停态没有任何帧可用
- **toast 只保留一次性事件**，常态信息交给徽章，避免同一事件三个通道
- `replayAnim(el, cls)` **合并不了重排**（三个不同元素）。要么一次消行里统一 remove → 只读一次 `document.body.offsetWidth` → 统一 add，要么用 `el.getAnimations().forEach(a => { a.cancel(); a.play(); })` 完全不碰重排
- **`prefers-reduced-motion` 是每加一个特效就要同步加的门** —— 现有那个 block 只覆盖了满级光环和 `#board` 的 transition；震屏对部分人是晕动症诱因

### E3. 音乐音效

- 套数**先做 1 套新的听效果再定** —— 全是单双振荡器合成，"柔和"和"厚重"的实际差别可能没描述的大。（v2 在 §3.4 写 3 套、阶段 2 表格写 2 套、验收写 9 种组合，2×2=4，自相矛盾）
- **`setTempo(bpm)` 必须是独立入口**，只改 `EIGHTH`，绝不碰 `mAt` —— `musicStart` 的早退会让"改 BPM 再调 musicStart"静默失效
- **`switchTrack()` 统一切歌**并重置 `mIdx`/`mBar`/`mBeat`，`scheduleMusic` 包 try/catch 降级静音
- 每曲独立 sub-gain，**disconnect 时机由最后一个已排期音符的 `o.stop` 推出来**，别写死 400ms
- FEVER 变速和危险加速合进一个优先级解析器；危险状态逐帧判定必须**加滞回**（进 3 行、出 5 行）
- 回归新增："播放中切歌 → 锁屏 → 解锁"

### E4. 疯狂版

- **JS 不复制，但 HTML 会复制** —— `tetris/index.html` 有 38 个 ID 且 `init` 里 10 处 `addEventListener` 无 null 守卫，少一个就白屏。`crazy/index.html` 应该由 `bump.py` **生成**，验收补一条"疯狂版全量回归"
- **只隔离 3 个 key**（`STORE_KEY` / `SAVE_KEY` / `WIPE_KEY`），偏好类（muted / buzz / music / skin）共用。v2 写"7 个全部隔离"和正文"偏好类共用"自相矛盾，而且 7 这个数在 v2 内部就过期了（教学 key、legacy、难度选择还要再加）。验收改成"所有 `localStorage` 访问经 `nsKey()` 统一入口，grep `localStorage.` 不得出现裸字符串"
- **`WIPE_TOKEN` 要拆成按 NS 取值的两个常量**，否则为标准版 bump 会连带清掉疯狂版
- **黄金块只做 `game.piece.mod` 实例属性** —— `holdPiece` 只搬 type，天然实现"进 hold 就掉金"，盘面一个字节不用动。v2 写的"`queue`/`hold` 升成 `{type,mod}` + 存档迁移"是把简单问题做复杂了（而且 board cell 才是更贵的一层）
- **不要新增 type key** —— `colorOf` 查不到会让 `mix()` → `hex(undefined)` 在 `h[0]` 当场 TypeError（v2 写"静默沿用上次颜色"，理由是反的）
- **行雨必须 `if (clearing) return;`** —— `clearing` 期间 `game.board` 还没塌陷，插一次行雨会让 `clearing.rows` 行号全部失效
- 行雨的语义必须写死：**不计 lines、不给分、不影响 combo/b2b**，优先清灰线行；触发改成明确的濒死豁免或加次数上限 —— 原设计"距顶 3 行每块 4%"约 0.04 行/秒，恰好对冲灰线的 0.04~0.05 行/秒，**最优解会变成"赖在危险区不消行"**
- FEVER：触发**每次消行掷一次**（按行数加权），计时挂 `game.elapsed` 且**期间禁用暂停和样式面板**；"重力减半"换成"灰线暂停"（重力本来就不痛，普通档 713ms/格）
- FEVER 换肤**不能写 `skin.pal`**（会被 `writeSkin` 持久化、污染用户选择），走独立 `activePal`
- **背景流动不能进 canvas** —— 格线烘在 `bgCv` 里，让它流动等于每帧重画 200 个圆角矩形
- 阶段第一件事：往 `bump.py` 的 `TARGETS` 加 crazy 条目并验证 `sw.js` 里出现 `./crazy/`。`TARGETS` 是手维护的、替换用纯正则，**`tetris.js` 这个串在 `../tetris/tetris.js` 里也能匹配上，两条路径书写顺序错了会互相污染**
- 教学弹窗**单独一层 DOM，不复用 overlay**（overlay 是单例三态，切后台会被暂停面板顶掉）；触发改成"打标记 + 等 `clearing` 结束再弹"；冻结统一走 `freeze(on)` helper 把 `resumeLoop()` 收在里面
- 离线页面数：加了 crazy 是 **6 个**不是 5 个；疯狂版图标要**新画**，否则主屏两个一模一样

## F. 性能红线

- **基线口径**：现在说的"60fps"指 **rAF 不掉帧**。正常帧绘制限在 30fps，但**消行那 260ms 是满帧的**，塌落动画按 60fps 算预算
- `wantsFrame()` 聚合函数要提到 tick 顶部**统一判**，clearing 分支也走同一个节流 —— 只加在 `:1529` 会漏掉它
- **只动 `transform`/`opacity` 的才是合成层。边框类效果是例外**（box-shadow，38~150px blur，手机上最贵的动画之一），危险脉动和跑马灯都要用"预先画好的发光图层 + 只动 opacity"
- canvas 继续用 dirty flag；**塌落动画属于"特效要改静态层内容"这一类**，`wantsFrame()` 覆盖不到，要单独处理
- **粒子和新增特效不用 `shadowBlur`**（`drawCell:818` 现在还在用，所以不能写"绝不用"）
- 每加一组特效跑一遍五个压力场景
