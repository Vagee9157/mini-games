### `countHoles` 比 agent 说的还便宜

它不只是「现成」—— **新增洞数已经在每次锁定时算好了**：

```js
const holesBefore = CRAZY ? countHoles() : 0;
...
const made = countHoles() - holesBefore;
if (made >= 4) tip('……没事', 5000);      // 目前只用来发一句自嘲
```

`made` 这个值已经存在，现在唯一的用途是嘲讽玩家。
**L27 无洞连击链 / M29 平整度分 的核心计算量是零** —— 只要拿 `made === 0`
去延长一个 streak。这是整个清单里性价比最高的一条，而且是三个 agent
里有两个独立指向的那个空白。

### 「后台变难」这条是假的

完整的保护链，三道：

1. `visibilitychange` → `saveGame(true)` + **自动暂停**
   （源码注释原话：「切到后台自动暂停，回来不至于已经死了」）
2. 暂停期间 `stepOnce` 立刻 `return 'stop'` → `tick` 取消 rAF
3. 恢复时 `resumeLoop()` 重置 `lastFrame = performance.now()`

所以 **K6「灰线按操作节奏走」解决的是一个不存在的问题**，可以从清单删掉。
**K5「回来缓冲」价值也大减** —— 回来时游戏是暂停态，本来就有时间看盘面，
剩下的价值只有「暂停覆盖层挡住了盘面」这一点点。

## 二、我自己查出来的真问题

### `step()` 的 dt 夹得太松（建议修）

```js
let left = Math.min(Math.max(dt, 0), 600000);   // 夹到 10 分钟
do { const d = Math.min(left, 100); ... } while (left > 0);
```

一个 10 分钟的 dt 会被切成 **6000 次 100ms 补算**，瞬间推进十分钟的
灰线、事件、重力。实测直接喂 `step(120000)`：

| 喂进去的 dt | 结果 |
|---|---|
| 30s | 落 1 块，灰线 +1，还活着 |
| 60s | 落 3 块，堆顶升到第 17 行 |
| **120s** | **落 12 块，堆顶到 0，`over = true`，当场打死** |

现在被上面那条暂停链挡着，所以线上没出过事。但这是**单点防护** ——
只要有任何一条路径让大 dt 进到 `step()`（iOS 上 `visibilitychange` 的边角
情况、主线程长阻塞、调试器断点恢复），一局就没了。

**建议把上限从 600000 夹到 2000。** 超过 2 秒的 dt 不是「游戏时间」，
是卡顿或挂起，按真实时间补算没有任何意义。改一个数字，消掉一整类灾难。

## 三、对清单本身的批评

### 1. 成本估计系统性偏乐观

agent 标的「低成本」基本只算了**核心逻辑**。这个仓库里一个改动真实要做的是：

- 核心逻辑
- 说明书**现算**（写死数字迟早过期，这个 session 已经抓到过两次说谎）
- 标准版隔离（照 `rollMod` 那种自己守门的写法）
- 存档兼容（`restoreGame` 要能吃老存档）
- **平衡影响：算平均贡献，决定要不要重标梯子**
- 性能验收（4× 降频跑满帧）
- 和现有 9 个事件 / 5 种变异块 / 梭哈 / 热度 / 冻结行的交互测试

本 session 的实证：删一个燃点，连带牵出 **5 个热度常量重标 + 倍率分档重标
+ 梯子重标 + 清档**，外加两个坑（TDZ、内联样式压不过 CSS）。
那在清单里会被标成「低成本」。

### 2. 165 条不是方案，是素材库

本 session 实际完成约 12 个改动，每个含验证平均 1~2 小时。
按这个吞吐，165 条 ≈ 几个月。清单的价值**不在「全做」，在于确认哪些是真空白**。

### 3. 三个 agent 都有「为了凑数而凑」的尾部

每份的后 1/3 明显变水（M 系列的格子属性四条、L 系列的 L8 双层盘面、
E 系列十一条新方块）。**真正有信息量的是前 1/3 和那几条「你没看见的前提」。**
