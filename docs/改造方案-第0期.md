# 项目一：dt 夹紧（止血）

## 问题

`step(dt)` 把 dt 夹到 `600000`（10 分钟），再按 100ms 切片补算：

```js
let left = Math.min(Math.max(dt, 0), 600000);
do { const d = Math.min(left, 100); left -= d; r = stepOnce(d); } while (left > 0);
```

一个 10 分钟的 dt 会被切成 **6000 次补算**，瞬间推进十分钟的灰线、事件、重力。

实测（直接喂 dt，绕过暂停链）：

| dt | 结果 |
|---|---|
| 30s | 落 1 块，灰线 +1 |
| 60s | 落 3 块，堆顶升到第 17 行 |
| **120s** | **落 12 块，堆顶到 0，当场判死** |

## 为什么现在没出事

三道保护：`visibilitychange` 自动暂停 → 暂停时 `stepOnce` 立刻 `return 'stop'`
→ 恢复时 `resumeLoop()` 重置 `lastFrame`。

但这是**单点防护**。任何绕过它的路径（iOS 上 `visibilitychange` 的边角情况、
主线程长阻塞、调试器断点恢复、系统休眠唤醒）都会让大 dt 直接进 `step()`。

## 改法

```js
// 600000 → 2000
let left = Math.min(Math.max(dt, 0), MAX_CATCHUP);
```

新增常量 `const MAX_CATCHUP = 2000;`，注释写明：**超过 2 秒的 dt 不是
「游戏时间」，是卡顿或挂起，按真实时间补算没有任何意义**。

## 边界

- 正常帧 dt ≈ 16.7ms，4× 降频下 p99 ≈ 19ms，离 2000 远得很，不影响正常游玩
- 暂停链仍然保留，这条是第二道防线不是替代品
- 2000 的选择依据：允许一次最长 2 秒的卡顿被如实补算（比如切后台瞬间、
  长 GC），再长就宁可丢帧也不要凭空推进游戏

## 验收

- [ ] `step(120000)` 之后游戏**不再**被打死，推进量 ≤ 2 秒
- [ ] 正常对局手感无变化（4× 降频 30 秒仍满帧，行数/块数与改前同量级）
- [ ] 暂停 → 恢复路径仍然正确

# 项目二：无洞连击链（填真空白）

## 问题

现在所有加成 —— 热度、连击、B2B、压哨、热流、险区、FEVER、深局 ——
**奖励的全是「消行速度」，没有一个奖励「整洁」**。
而整洁恰恰是深局能不能活下去的唯一变量。于是理性打法永远是贪消行，深局必然崩。

三个 agent 里有两个（街机设计角度、计分规则角度）**独立**指向这个空白。

## 为什么它几乎免费

`lockPiece` 里已经有：

```js
const holesBefore = CRAZY ? countHoles() : 0;
...
const made = countHoles() - holesBefore;
if (made >= 4) tip('……没事', 5000);     // 目前唯一用途：嘲讽玩家
```

**`made`（这一手新增几个洞）已经每次锁定都在算**，核心计算量为零。

## 设计

```
每锁定一块：
  made === 0  → cleanRun++
  made  >  0  → 结算：按 cleanRun 的峰值给一次性热度，然后清零
```

- 常量：`CLEAN_MIN = 8`（低于这个数不结算，免得每两三块就弹一次）
- 奖励：`heat += CLEAN_MIN 起步的递增值`，**给热度不给分**
  —— 给分会直接动分数曲线、要重标梯子；给热度只是让你更容易维持倍率，
  而且热度有衰减兜底，不会无限累积
- 显示：右侧状态框第四行「整洁 N 块」，断链时走飘字（不走 toast，
  toast 是共享通道会被顶掉 —— 这条教训本 session 已经吃过两次）

## 为什么给热度而不给分

本 session 的铁律：**任何给分的机制都要先算平均贡献、再决定要不要重标梯子**。
给热度则落在已有的衰减平衡里（稳态 ≈ 注入速率 × `HEAT_TAU`），
影响可控且可测。第 0 期的目标是「不动倍率曲线」，给分会破这条。

## 边界

- 标准版：`made` 的计算本来就在 `if (CRAZY)` 里，天然隔离，但仍照
  `rollMod` 的写法让新函数**自己守门**
- 和现有连击（`game.combo`）是两条独立的链：一条数消行、一条数整洁，
  可以同时亮。状态框只有三槽，优先级要定（见下）
- 道具消行（`clearFullNow` 那条路径）不经过 `lockPiece`，所以不影响 `made`
- 重开/续玩要复位 `cleanRun`

## 状态框三槽的优先级（现有逻辑要改）

当前：梭哈待接 > 梭哈进行 > 事件 > 燃点 > FEVER > 狂欢 > 热度，取前三。
整洁链插在**狂欢和热度之间**：它是常驻信息，优先级低于所有限时的东西。

## 验收

- [ ] 连续 N 块不造洞 → 链在涨；造一个洞 → 立刻断并结算
- [ ] 结算给的是热度不是分数
- [ ] 标准版完全不触发
- [ ] 重开后链归零
- [ ] 状态框在「梭哈 + 事件 + FEVER」同时存在时不显示整洁链（槽位不够），且不报错

# 项目三：体面收手（补结构洞）

## 问题

**一局只有一种结束方式：死。**

打到第 12 分钟手累了、地铁到站了、心态崩了 —— 现在唯一的出路是
**故意把方块堆到天上**，而那个动作本身会把前面 12 分钟的好心情一起毁掉。

## 设计

- 入口：暂停页加一个「收手」按钮（暂停页本来就是"我想停下来"的地方）
- 行为：走 `endGame('收手')`，分数**全额**计入最高分 / 生涯 / 今日 / 段位
- 门槛：`isRealRun()`（已有：30 块或 60 秒）才显示这个按钮 ——
  否则秒开秒收会污染「今日局数」和狂欢局保底计数
- 结算页：`DEATH_TEXT` 加一条 `'收手': '见好就收'`，
  `runTitle` 加一档（峰值/连击等都不满足时，收手局给「收手」而不是「稳」）

## 为什么不怕被滥用

收手和死亡的**结算完全一样**，没有任何额外好处 —— 它不是一个 buff，
只是一个体面的出口。玩家没有理由为了刷分而收手（收手拿到的就是当前分数，
继续打只会更高）。

## 和狂欢局保底的交互

`countRush()` 在 `endGame` 里按 `isRealRun()` 推进 —— 收手局同样是有效局，
照常推进保底计数。这是对的：你确实打完了一局。

## 边界

- 收手时如果正在 FEVER / 燃点 / 梭哈窗口里：`endGame` 已有 `feverEnd()` 处理，
  其余瞬态由 `crazyReset()` 在下次重开时清。要验证收手后立刻重开不残留
- 收手要 `clearSave()`（`endGame` 路径上已有）

## 验收

- [ ] 暂停页出现「收手」，且只在有效局之后出现
- [ ] 收手后分数全额计入最高分/生涯/今日
- [ ] 收手局照常推进狂欢局保底计数
- [ ] 结算页文案正确
- [ ] 收手 → 重开，无瞬态残留（FEVER 样式、梭哈面板、事件 data 属性）

# 项目四：今天的线（换参照系）

## 问题

**唯一的参照系是历史最高分，而那是个被设计成追不上的数。**
所以 99% 的局结束时的默认感受都是「又没破纪录」。

这条也顺带否掉了之前被我推荐的「幽灵回放」——
那东西**追的也是最高分，只会加重同一个问题**。

## 设计

- 存最近 N 局的分数（`N = 10`），滚动数组
- 目标线 = `中位数(最近5局) × 1.2`，开局就显示在侧栏
- 过线：当场飘字 + 结算页标出「过线了」
- 不足 3 局时不显示（样本太少，给出来的线没有意义）

## 存储

复用 `DAILY_KEY` 的存储风格，新增 `RECENT_KEY = nsKey('recent.v1')`：

```js
{ v: [分数, 分数, ...] }      // 最多 10 个，新的 push 到尾部
```

- 只记 `isRealRun()` 的局
- 和清档令牌的关系：清档只清 `STORE_KEY`/`SAVE_KEY`，
  **recent 不清** —— 它是「最近水平」不是「历史战绩」，清了反而失去意义

## 为什么是中位数 ×1.2 而不是平均 ×N

中位数抗离群值（一局爆发或一局秒死都不该把线带偏）。
×1.2 的依据：让大约**一半**的局能过线 —— 目标是「经常能赢一次」，
不是「再立一个追不上的标杆」。首版取 1.2，上线后看真实过线率再调。

## 边界

- 第一次玩（`recent` 为空）：不显示
- 清档之后：`recent` 保留，所以线仍然有效
- 标准版和疯狂版各有各的 `recent`（`nsKey` 天然隔离）

## 验收

- [ ] 不足 3 局不显示
- [ ] 线 = 最近 5 局中位数 ×1.2，且只统计有效局
- [ ] 过线当场有反馈，结算页也标出
- [ ] 清档后线仍在
- [ ] 两个版本的 recent 不串

# 统一验收（每条做完都要跑）

1. **说明书对账** —— 新常量必须出现在说明书里且**现算**（本 session 抓到过两次说谎）
2. **标准版隔离** —— 新机制自己守 `CRAZY` 门禁，照 `rollMod` 的写法
3. **4× 降频性能** —— 基线：FPS 60.0 / p99 < 20ms / 卡顿 0 / 长任务 0 / 内存 9.5MB
4. **存档往返** —— 新状态要么进存档，要么在 `crazyReset` 里复位，不能半吊子
5. **两版冒烟** —— 标准版三个倍率仍恒为 1

# 明确不在本期

- 任何动热度量程 / 倍率曲线 / 深局形状的改动（会触发梯子重标）
- 波次制、热度商店、三选一（第 2 期，且波次制和局内升级要先二选一）
- 推列、Zone、灰线债务条（第 1 期）
- 幽灵回放（已降级，理由见上）
